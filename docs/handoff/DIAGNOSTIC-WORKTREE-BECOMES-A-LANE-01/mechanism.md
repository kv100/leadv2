# Механизм угона активной задачи — найден 2026-09-02

Оставшийся артефакт: `docs/handoff/PHASE-PATH-REPRO-01/pulse.json`

```json
{"ts":"2026-09-02T14:26:10Z","pid":92204,"task_id":"PHASE-PATH-REPRO-01","phase":"","tool":"Bash",
 "last_tool_at":"2026-09-02T14:26:10Z","nesting":0,"session_id":"c5502377-...-470f"}
```

`session_id` здесь — сессия **лида**, не субагента. Хук, срабатывающий на Bash, записал имя чернового
worktree как `task_id` и привязал его к сессии лида. Дальше `LEADV2_PHASE_HINT` и `ORCHESTRATOR_ROLE`
читают этот файл и выдают лиду `ACTIVE TASK: PHASE-PATH-REPRO-01 | phase: spawning` вместе с полным
ролевым блоком оркестратора.

**Активная задача лида переписывается любым bash-вызовом субагента внутри произвольного worktree** —
без строки в реестре, без записи в журнале диспатчей, без участия лида. Наблюдено дважды подряд: пульс
напечатал `live=0: PHASE-PATH-REPRO-01=нет-журнала; PHASE-PATH-REPRO-01=нет-журнала`, то есть одну и ту
же несуществующую линию два раза, и при этом честно сказал `live=0` — он сам знал, что живых линий нет,
и всё равно назвал имя.

Требование усиливается: личность активной задачи не выводится из имени каталога, в котором случайно
выполнилась команда. Она приходит из реестра и только для задач, которые лид действительно взял.

Негативный контроль: выполнить bash в постороннем worktree → активная задача лида не меняется;
вернуть старое поведение → проба краснеет.

## Почему это не мелочь
Сегодня это стоило только путаницы. Но тот же путь означает, что бриф, фазовые подсказки и ролевые
инструкции лида могут быть переписаны именем каталога, созданного не лидом. Для сессии, которая
принимает решения о диспатче на основании «какая у меня активная задача», это подмена входных данных
через побочный эффект чужой команды.
