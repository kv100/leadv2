# DISPATCH-HANDLE-SLICE-UNATTRIBUTED-01 — отчёт

Бриф прочитан целиком, и код прочитан после него. **Половина брифа уже неверна**, потому что за
дни после его написания одну из двух рук починили. Пишу это первым, потому что доделывать работу
до объёма брифа, когда предмета уже нет, — худший из возможных исходов ряда.

## Что изменилось с 2026-09-01

Бриф описывает **две** руки с делением строки пополам, glm и kimi.

- **glm — почини́ли до меня.** GLM-ARM-THROUGHPUT-01 снял деление и оставил в коде развёрнутое
  объяснение: `glm-coder.sh` `bg` печатает голый run_id ОДИН раз, а деление пополам резало каждый
  хэндл в мусор, который `status` никогда не разрешал, — то есть glm-flash **вообще не
  запускался** через роутер. Сейчас там `handle="${out%$'\n'}"`.
- **kimi — деление осталось**, вместе с комментарием «format is `$RUNS/$handle$handle`».
- Пункт [Critical] 2 брифа (отказ от неверифицируемого хэндла) **уже реализован на обеих руках**:
  пустой хэндл → `spawn_failed reason=empty_handle`, и сразу за ним `status <handle>` →
  `spawn_failed reason=not_live`. Дописывать было нечего.

Так что ряд свёлся к одной руке — и к вопросу, верна ли для неё посылка брифа.

## Посылка проверена у источника, а не по комментарию

```
kimi-coder.sh:94    echo "${run_id}"          <- одна копия, без префикса пути
glm-coder.sh:101    echo "${run_id}"          <- ровно то же
```

Комментарий в диспатчере утверждал `$RUNS/$handle$handle`. Лаунчер печатает одну копию. Значит
`handle="${_kimi_temp:0:_kimi_half}"` резал каждый kimi-хэндл пополам, `status` его не разрешал, и
рука падала в `spawn_failed not_live` — тот же дефект, что нашли и починили на glm, оставленный
живым на соседней руке.

Живого следа в журналах нет и я его не выдумываю: в корпусе 21 линии **ни одного** kimi-спавна
(24 события `kimi_skipped`, ноль `worker_spawned model=kimi`). Доказательство здесь —
код лаунчера плюс сюита, а не журнал.

## Правка

Одна строка, зеркало glm-руки: `handle="${out%$'\n'}"`. Отказ по круговому обходу (`status`) уже
стоял ниже и остаётся единственным судьёй того, что хэндл называет реальный прогон.

## Сюита и оба цвета

`plugins/leadv2/scripts/tests/test-spawn-handle-parse.sh` — **12/0**. Она не копирует логику
парсера: python вырезает строку присваивания **из самого диспатчера** во время прогона и исполняет
её, поэтому судит отгруженный текст, а не его копию.

| случай | что закреплено |
|---|---|
| (a) | настоящий `kimi-coder.sh bg` печатает непустую строку без `/` |
| (b) | эта строка **не** сдвоенная (посылка старого парсера ложна) |
| (c) | продакшн-парсер возвращает хэндл лаунчера без изменений |
| (c2) | `status` разрешает разобранный хэндл — он называет реальный прогон |
| (d) | три синтетические формы (чётная, нечётная, `dup-dup`) проходят целиком |
| (e) | контроль: вернуть деление в копию диспатчера → парсер режет |

Второй цвет снят прогоном, а не рассуждением: сюита, направленная на мутированную копию
(`KIMI_HANDLE_SUITE_DISPATCH`), даёт **6/6** — краснеют (c2) и все три (d).

**Дефект в собственном контроле, найденный этим же прогоном.** Случай (e) сначала проверял только
«в копии есть `_kimi_half`». На мутированном дереве вставка не находит якорь, python падает — а
строка `_kimi_half` там уже есть, и контроль читался ЗЕЛЁНЫМ над неприменённой мутацией. Теперь он
проверяет код возврата самой вставки: контроль обязан подтверждать, что мутацию наложил ЭТОТ
прогон.

## Отбор CI доказан прогоном

```
LEADV2_RUN_ALL_SELECT_ONLY=1 bash tests/run-all.sh --scope changed
[SELECT] …/tests/test-spawn-handle-parse.sh
run-all: 118 selected, scope=changed, select_only=1
```
Саморегистрация через `# run-all-triggers: kimi-coder.sh leadv2-dispatch-code.sh` в шапке —
отдельной строки в карте не требуется. Строка каталога мутаций: `67`.

## Чего в сюите нет, названо прямо

Полного диспатча через настоящий арбитр на руку kimi. В герметичной фикстуре арбитр разрешается в
`freepool`, затем `sonnet` (замер 2026-09-06: `arbiter_pick=freepool`, `arm_excluded=glm:not_allowed`),
и увести его на kimi без фикстуры маршрутизации нельзя. Сюита закрывает контракт лаунчера и текст
парсера; сквозной путь спавна на соседней руке закрыт `test-glm-flash-handle.sh`.
