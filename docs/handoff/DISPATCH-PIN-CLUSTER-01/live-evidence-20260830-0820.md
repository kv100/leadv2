# Live evidence, 2026-08-30 08:10–08:25Z — collected while dispatching another lane

Four consecutive dispatch attempts of the SAME founder task
(`ANTI-SILENCE-STATUSLINE-01`, resuming an existing lane) were refused, each for a
different reason, before one launched. Every refusal is inside this cluster's scope.

## 1. `--resume-lane <founder-id>` does not bind `founder_task_id`

```
[leadv2-dispatch-code] lane_placement_pinned task=f41cf6c6 mode=resume-lane path=…/worktrees/ANTI-SILENCE-STATUSLINE-01 key=ANTI-SILENCE-STATUSLINE-01
…
[leadv2-dispatch-code] prepass_parked task=f41cf6c6 founder_task_id= reason=no_design_after_2_attempts last_reason=no_lane_writes
```

The placement pin resolved the founder id (`key=ANTI-SILENCE-STATUSLINE-01`) and then
`founder_task_id` was still empty two guards later. `_lane_writes_guard`
(`leadv2-dispatch-code.sh:3443`) uses `founder_task_id` for its third and most forgiving
admission path — "an existing lane worktree; isolation substitutes for a declaration". The
lane worktree existed the whole time. The guard could not see it because the id the
placement step had already resolved was not propagated. So: **`--resume-lane` alone can
never satisfy the writes guard, no matter how real the lane is.** `--task-id` (undocumented
— absent from `usage`) is currently the only way to bind it.

## 2. Editing the mission rotates the signature, which discards recorded phases

`f41cf6c6` → `d09fd656` → `73bc78d3` across three edits of the same mission file. Each new
sig8 arrives with `missing=diverge,plan,gate1` and has to have its phase artifacts
hand-copied and re-recorded before it may dispatch. A round that iterates on its own brief
pays a full phase-recording cycle per iteration, for a task whose plan never changed.

## 3. The `no_lane_writes` refusal names no remedy

The dispatcher prints `reason=no_lane_writes` and then parks, but never says what grammar it
wanted. It accepts a `LANE_WRITES: a,b,c` line in the mission (harvested by `_prepass_writes`,
`:3318-3333`) — a prose "Write set:" section with markdown bullets, which reads as the obvious
declaration to any worker or lead, satisfies nothing. Two of the four refusals above were spent
discovering this.

## 4. `leadv2-glm-quota-gate.sh:159` — backticks in an unquoted heredoc (FIXED)

Every GLM quota refusal printed `glm_quota_gate_80: command not found` to stderr, because the
`<<EOF` body interpolates and the exception id is written in backticks. The heredoc cannot be
quoted (it interpolates `${THRESHOLD}` and `${tripped}`), so the backticks are now escaped.
Fixed in the main checkout this session; `bash -n` clean. Not part of this cluster's diff.
