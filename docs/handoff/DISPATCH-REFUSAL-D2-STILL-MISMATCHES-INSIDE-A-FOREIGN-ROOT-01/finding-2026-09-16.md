# D2 residue: same code, same environment, different worktree, different verdict

Row `0c47591a2f27`. Measured by the lead 2026-09-16 while checking whether this row had gone stale.
It has not. The finding is sharper than the original.

## Why the row was suspected of being stale
`test-dispatch-refusal-truth.sh` runs **rc=0 from main** today (55s, macOS Darwin 25.6.0, commit
`fa378236`). The census counted it red, and the parent row `DISPATCH-REFUSALS-LIE-ABOUT-THEIR-CAUSE-01`
was fixed and merged after the census was taken — so "the red is stale" was the obvious reading.

## What actually happens
Run the suite with `LEADV2_PROJECT_ROOT` pointed at a foreign repo, from inside a leadv2 lane
worktree. The verdict depends on **which worktree**:

```
cwd=.claude/worktrees/689648a9641b   LEADV2_PROJECT_ROOT=~/Projects/persona-engine
  [DISPATCH-REFUSAL-TRUTH] pass=6 fail=0
  PASS: D2 untracked mission names the state and git remedy
  PASS: D2 absent mission remains a distinct disk-absence refusal

cwd=.claude/worktrees/ce3da635       LEADV2_PROJECT_ROOT=~/Projects/persona-engine
  FAIL: D2 untracked refusal mismatch rc=5:
    [leadv2-dispatch-code] WARN: foreign project root detected
      (env=/Users/kostiantyn.vlasenko/Projects/persona-engine cwd=/Users/kostiantyn.vlasenko/Pr...)
  [DISPATCH-REFUSAL-TRUTH] pass=5 fail=1
```

Two runs were made against `689648a9641b` — once invoking main's copy of the suite by absolute path,
once invoking the worktree's own copy — and both were 6/0. So the green side is not an artifact of
which copy of the suite was executed.

## The explanation that was ruled out
The obvious hypothesis was that `ce3da635` is an old checkout missing a fix that main has. It is not:

```
ce3da635      HEAD=7539c27d   leadv2-dispatch-code.sh md5=ab5b24acf3d50a3ac6bdc84887968c95
689648a9641b  HEAD=95a5255a   leadv2-dispatch-code.sh md5=ab5b24acf3d50a3ac6bdc84887968c95
main          HEAD=0b2a3fb7   leadv2-dispatch-code.sh md5=ab5b24acf3d50a3ac6bdc84887968c95
```

**Byte-identical dispatcher in all three.** The code version is not the variable.

## What this means for the row
The defect is real, currently reproducible, and depends on some property of the surrounding checkout
rather than on the dispatcher's version. D2 asserts that an **untracked** mission produces a refusal
naming the state and the git remedy, so the first place to look is whatever makes a file read as
untracked differently between two worktrees of the same repository — index state, `.git` file vs
directory, a stale `info/exclude`, or a `docs/tasks.yaml` / `.claude/` override present in one tree
and not the other.

That is a hypothesis, not a finding. Nothing above establishes it.

## Boundary
Two worktrees tried, one green and one red, three runs total, macOS Darwin 25.6.0, 300s ceiling, all
with the same byte-identical dispatcher. Not tried: other worktrees, a fresh worktree created today,
or the same test from a non-worktree clone. A lane taking this row should start by widening that
sample, because "1 of 2 worktrees" is far too small to name a mechanism from.
