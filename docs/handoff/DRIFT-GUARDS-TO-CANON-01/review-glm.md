## Критическая проблема (блокирующая)

**1. HIGH — Проверка перед коммитом пропускает именно тот случай, для которого была создана** (`plugin-scripts-drift-guard.sh:51`)

`--diff-filter=ACMR` пропускает `T` (typechange). Замена отслеживаемого symlink на реальный файл и его стейджинг записывается git как `T`, а не `M`. Проверка в изолированном окружении (/tmp/drift-probe, symlink `foo.sh` → реальный файл, `git add`):

```
$ git diff --cached --name-only --diff-filter=ACMR -- '.claude/scripts/*.sh'
(пусто)
$ git diff --cached --name-status -- '.claude/scripts/*.sh'
T  .claude/scripts/foo.sh
$ git ls-files -s -- .claude/scripts/foo.sh
100644 5d1bb36... 0  .claude/scripts/foo.sh
```

И запуск проверки end-to-end в том же стейджинге вернул **RC=0** (без блокировки, без вывода). Проверка срабатывает только для `A` (новый файл, symlink никогда не отслеживался) или `M` (уже перенесенная копия изменена). Классификатор внутри (`ls-files -s` mode ≠ 120000 → REGRESSION/DRIFT) работает корректно — но к нему никогда не обращаются. Смягчение последствий: session-warn обнаруживает это в рабочем дереве при *следующем* запуске сессии, поэтому перенесенную копию можно закоммитить и запушить на протяжении всей текущей сессии без препятствий. Исправление однострочное: `--diff-filter=ACMRT`.
