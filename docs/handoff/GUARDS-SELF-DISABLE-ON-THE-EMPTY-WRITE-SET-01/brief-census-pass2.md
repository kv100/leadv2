# Guards-self-disable census — pass two

Scope: the ~55 remaining candidates from the pinned grep (57 found live on `main`, vs 59 at
brief-authoring time — small drift, not re-scoped) after excluding pass one's four
(`leadv2-dispatch-product-close.sh:1803`, `:1911`, `_dl_derive_lane_state`,
`lib/leadv2-mission-writeset.sh:134`). Criterion, mechanics, and cascade requirement taken
verbatim from `docs/handoff/GUARDS-SELF-DISABLE-ON-THE-EMPTY-WRITE-SET-01/brief-census-criterion.md`.
No keyword re-filter was applied — every remaining candidate was read.

Key correction made during this pass: `docs/handoff/dispatch-*/` in the **leadv2 plugin repo**
is NOT where glm/freepool/kimi-coder.sh write their run artifacts — those go to
`~/.claude/cache/{glm,freepool,kimi,claude}-runs/<id>/` (`GLM_RUNS_DIR` etc., defaulting there).
An initial measurement against `docs/handoff` showed 0/821 `.deliverable` files and looked like
a 100%-broken pipeline; re-measuring against the real run-cache directories gave the true,
non-zero-but-still-damning ratios below. Recorded here so a future pass doesn't repeat the
mistake.

## Notes on measurement quality

- Findings A/B/C are the strongest in this pass: real counts from real, currently-populated
  run-cache directories (`~/.claude/cache/{glm,freepool,kimi}-runs/`), not log-mining or inference.
- Finding D is a clean, unambiguous 100%: grep across the entire plugin tree for the one env var
  that would ever flip the guard on, found only in a test file.

  runtime evidence (positive or negative) was recoverable from the artifacts on disk for the exact
  triggering condition, even though the code shape (fail-open + printed marker) matches the hunted
  pattern closely enough to be worth recording.
