## Второй фильтр — заменённый, а не тот же

Проход один отбирал по словарю переменных (`writes|scope|paths|lane|protect|dirty|files`).
Проход два меняет ось: **чем называет себя объемлющая функция** — `gate|guard|assert|verify|
enforce|refus|block|deny|require|precheck|preflight|check`. Строка попадает в список, только если
ранний `return 0` стоит внутри функции, которая сама заявляет себя защитой.

```
кандидатов (ранний return 0 на пустом входе): 64
оставлено фильтром прохода два:               16   (25%)
на верхнем уровне, без объемлющей функции:      2   (отброшены: не защита)
```

Шестнадцать живут в девяти файлах: `_foreign_check`, `_codex_quota_gate`, `deadhand_check`
(×3 копии в *-coder.sh), `_burn_gate`, `_lane_writes_guard`, `pc_precheck_writes`,
`pc_stop_gate_autocommit`, `check_pin_drift`.

## Тест допуска: доля, а не правдоподобие

Ранний выход на пустом входе сам по себе не дефект — это может быть законное «проверять нечего».
Дефект — когда пустой вход **это и есть популяция**, и защита об этом молчит. Поэтому к каждой
находке требуется измеренная доля реальных вызовов, попадающих в слепую ветку.

### Допущена одна: `_foreign_check` (leadv2-reply-router.sh:67) — доля 100%

```
leadv2-ask.sh:176   OWNER_SESSION="${LEADV2_ASK_OWNER_SESSION:-${CLAUDE_SESSION_ID:-}}"
                    ни одна из двух не выставлена в процессе, который спрашивает
q-*.yaml, где поле есть:  8283  (8057 в ~/.claude/leadv2-state/*/questions/
                                 + 226 в <repo>/docs/leadv2/questions/)
из них owner_session != null:   0
```

**Поправка к собственному замеру (внесена лидом, 2026-09-06).** Сначала я написала «строка
"owner" встречается в 0 из 8270 файлов». Вывод верен, прибор — нет: я считала по одному каталогу
и по шаблону, который не совпал. Поле **есть и пишется** — просто всегда `null`, что
`yaml.safe_load` даёт как `None`, а `print(v if v else "")` превращает в пустую строку. Правильная
формулировка сильнее прежней: не «поля нет», а «механизм работает, отчитывается и не несёт ни
одного значения». Правильный вывод на сломанном приборе — всё равно сломанный прибор: в следующий
раз он выведет не туда.

Ветка с комментарием «old row (pre-OWNERSHIP) → always allow» — не исключение, а вся популяция.
Защита от ответа на чужой вопрос **не сработала ни разу** и не сказала об этом ни слова: снаружи
«не смог проверить» читалось как «проверил, вопрос твой». Рядом вторая такая же — непарсящийся
`asked_at` тоже был молчаливым fail-open.

Зелёная сюита над этим есть — `test-question-delivery-ownership-01.sh`, 10/0. Она зелена потому,
что её фикстура **экспортирует `LEADV2_ASK_OWNER_SESSION`**: она проверяет поле, пустое в 100%
живых строк. Дыра не в продукте, дыра в приёмке.

### Отклонена — с измерением, а не по ощущению: `protection_derived`

Самый заметный кандидат класса (защита линии выводится из её набора записи) предпосылку **не
подтверждает**. По журналам 21 линии:

```
protection_derived всего:              21
из них с пустым набором записи:        17  (81%)
из этих 17 закончились НЕзащищёнными:   0
   все 17: write_class=unknown writes_protected=1 effective_protected=1
```

Пустой вход этот гейт не выключает — он ошибается **в сторону защиты**. Название ряда для него
ложно, и это тоже результат: класс «гвард самоотключается на пустом вводе» не общий, он про
`_foreign_check`. Остальные четырнадцать не измерены и потому не заявлены — не «чисто», а «не
проверено».

## Правка и парный контроль — оба цвета показаны

Правка не закрывает дыру стеной: `owner_session` пуст у 100% строк, так что отказ на пустом
вводе заблокировал бы **любой** ответ на машине. Пустая ветка по-прежнему возвращает 0 — но
теперь говорит `foreign-check UNAVAILABLE qid=… reason=no_owner_session`. То же для
`reason=unparseable_asked_at`.

Сюита `test-guard-says-when-it-could-not-check.sh` поднимает **настоящую** `_foreign_check` из
продукта (тот же yaml-разбор, та же арифметика возраста); подделан на уровень ниже только сам
файл вопроса. 5/0.

| прогон | (a) слепая ветка говорит | (b) слепая ветка пропускает | (c) чужой молодой отказан | итог |
|---|---|---|---|---|
| правка | ok | ok | ok (rc=6) | **5/0** |
| M1 — убрать printf в слепой ветке | **FAIL** | ok | ok | 4/1 |
| M2 — сделать в слепой ветке `return 6` | ok | **FAIL** | ok | 3/2 |

Обе мутации вставлены **внутрь тела** `_foreign_check`. M2 — тот самый важный цвет: правка, которая
превращает самоотключённый гвард в стену, валит сюиту, а не проходит её. Случай (c) зелен под
обеими: сама защита не тронута. Обе строки в каталоге (`64 → 66`), сюита зарегистрирована в
`run-core-offline.sh`. Существующая `test-question-delivery-ownership-01.sh` после правки 10/0.

## Прибор снова ошибся в мою сторону

Первый прогон дал (c) красным — «защита сломана». Причина в фикстуре: неквотированный
`asked_at:` PyYAML читает как datetime, `strptime` падает, возраст становится непроверяемым.
Это выглядело как третья слепая ветка. Живая строка `q-f46a59bb.yaml` пишет
`asked_at: '2026-09-06T11:53:39Z'` — в кавычках, разбирается как строка. Ветки нет, ошибка была
моя; фикстура исправлена, причина записана в её комментарии.

Четырнадцать оставшихся ранних выходов не измерены. Два из них живут в файлах, занятых соседними

недостижима (не «прошло молча» — вычислить нечего). Каждая строка — либо прогон сейчас, либо

### Граница популяции

16 — это не перепись всех гвардов плагина, а выборка ОДНОГО фильтра отчёта (функция называет
себя `gate|guard|assert|verify|enforce|refus|block|deny|require|precheck|preflight|check`, и
внутри нашлась ранняя `return` на пустом значении) поверх 64 кандидатов первого прохода (словарь
`writes|scope|paths|lane|protect|dirty|files`). Отдельно, той же строкой, `brief-census-pass2.md`
измерила ЕЩЁ восемь мест (A-H) другим фильтром (произвольный "тихий return 0 на пустом входе", не
завязанный на слово-гвард) — из них два (B/E) пересекаются с 16 по имени (`deadhand_check`,
`_codex_quota_gate`), остальные шесть (A, C, D, F, G, H) в список 16 не попали вовсе, хотя это тот
же класс дефекта. Значит правильная граница — минимум **24 уникальных места** (16 + 8 минус 2
пересечения), а не 16 и не 64: обе выборки — фильтры по словам, ни одна не перечисление всех
ранних `return` в плагине. Полная перепись потребовала бы либо третьего фильтра, либо разбора
AST; не строила — вне бюджета этого ряда.
