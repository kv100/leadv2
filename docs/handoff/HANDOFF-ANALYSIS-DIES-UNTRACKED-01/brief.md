# HANDOFF-ANALYSIS-DIES-UNTRACKED-01 — аналитика линий не попадает в git и умирает

Сначала прочитай `docs/handoff/RESUME-20260903/_shared.md` — общие правила приёмки.

## Замер

`.gitignore:49` игнорирует `docs/handoff/*/*`, а разрешающий список ниже пропускает только
`report.md`, `brief*.md` и `round*-red`. Всё остальное `git add` глотает **молча**: команда
отрабатывает, коммит проходит, файла в нём нет.

Перепись репозитория плагина 2026-09-03: **6072 неотслеживаемых файла** под `docs/handoff`.
По соглашению об именах — только 4, они уже закоммичены. За соглашением остаются настоящие
документы:

```
260  lane-mission.md          миссия каждой линии
 93  architect.summary.md     разбор архитектора
 93  architect.full.md
 62  developer.summary.md
```

Это ровно те артефакты, которые за один вечер терялись трижды: брифы жили в `/tmp` и умерли
вместе с сессией; четыре брифа одной волны не были закоммичены никогда; у другой сессии
проглотило 5 файлов из 8, включая **замороженную выборку миграции на 74 строки**, на которую
прямо ссылалась строка реестра отложенных решений. То есть у ледгер-строки была зависимость
от файла, которого git не видел.

## Задача

Сделать так, чтобы аналитика линий не могла исчезнуть незамеченной.

**Решение по `.gitignore` уже принято и не пересматривается:** список НЕ расширяем масками —
он защищает улики линий друг от друга, и «добавим ещё маску» это как раз то, чем такие списки
протухают. Норма — явный `git add -f` для лид-артефактов плюс проверка `git ls-files`.

Поэтому задача не в том, чтобы разрешить больше, а в том, чтобы **отсутствие файла в git
стало громким**. Реши сам и обоснуй, какой из классов выше обязан трекаться, и построй
проверку, которая ловит нарушение. Минимум, который обязан работать:

- каждый путь, упомянутый в `docs/leadv2/scheduled-decisions.md`, обязан быть в `git ls-files`;
- каждый путь, на который ссылается бриф линии как на своё доказательство, — тоже.

## Приёмка

1. Сюита берёт пути из `scheduled-decisions.md` и из брифов и требует
   `git ls-files --error-unmatch` по каждому.
2. Негативный контроль: убрать один такой файл из индекса (`git rm --cached`) — сюита обязана
   покраснеть. Доказательство — пара `baseline_rc`/`mutated_rc` и красная строка, НЕ `diff_hash`.
   Мутация вставляется ВНУТРЬ тела функции, не на верхний уровень файла: вставка на верхний
   уровень красит всё по неверной причине и читается как проход.
3. Сюита зарегистрирована в `EXTRA_SUITE_MAP` в `tests/run-all.sh` и раннер её ВЫБИРАЕТ —
   докажи прогоном `--scope changed`. Незарегистрированная сюита сгниёт молча: из 23 сюит,
   на которые опирался план, раннер видит 9.
4. Зелено на macOS И в linux-контейнере, оба кода возврата в отчёт.

## Границы

**Массовый коммит ~1000 файлов НЕ делать.** В репозитории работают линии; столкновение дороже
задержки. Задача — построить проверку, а не залить всё разом.

Правку `tests/run-all.sh` делай ТОЛЬКО дописыванием строки; не переформатируй и не двигай
существующие — три другие линии дописывают туда же, и трёхстороннее слияние должно остаться
тривиальным. Файл подменяй через временный и `mv`, а не правкой на месте: bash читает скрипт
по мере выполнения, и правка на месте способна испортить уже запущенный прогон.

Не трогать: `main`, `.gitignore`, `tests/known-red-suites.txt`, ослабление ассертов,
`plugins/leadv2/scripts/leadv2-dispatch-code.sh` (держит лид).
Свои заметки клади в `docs/handoff/HANDOFF-ANALYSIS-DIES-UNTRACKED-01/` и коммить через
`git add -f`, затем проверь `git ls-files` глазами — иначе исчезнут ровно так, как описано выше.
