# INVISIBLE-DELIVERABLES-CENSUS-01 — 68 готовых отчётов, которых git не видит

## Что случилось

Сегодня, 2026-09-03/04, выяснилось: воркеры линий не умирали. Они **дорабатывали до конца** и
клали результат в `docs/handoff/dispatch-<sig>/developer.full.md`. Этот путь молча игнорируется
`.gitignore:49` (`docs/handoff/*/*`); разрешающий список ниже пропускает только `report.md`,
`brief*.md` и `round*-red`. Лид смотрел `git log`, видел ноль коммитов, объявлял смерть и
переподнимал линию — а каталог диспатча ключуется сигнатурой задачи, а не попыткой, поэтому
новая попытка **перезаписывала поток предыдущей**.

Доказательство: последнее сообщение воркера пятой попытки D3 —
`DELIVERABLE_COMPLETE — see docs/handoff/dispatch-6134df79/developer.full.md`;
событие результата `"stop_reason":"end_turn"`; файл существует, 7 477 байт, открывается
строкой `verdict: APPROVE` и сообщает, что работа по сути готова.

**На диске сейчас 68 таких файлов.** Каждый может содержать выполненную работу, которую
никто не принял.

## Задача

Перепись. Не починка, не рефакторинг — **инвентаризация**.

Пройди по всем `docs/handoff/dispatch-*/developer.full.md` (и `developer.summary.md`, если он
есть рядом) и по каждому определи:

1. **вердикт** — первая строка часто содержит `verdict:` (`APPROVE` / иное);
2. **какой линии он принадлежит** — ищи идентификатор задачи внутри файла и в соседних
   `lane-mission.md` / `task-class.yaml` того же каталога;
3. **утверждает ли воркер, что работа завершена** — маркеры вроде `DELIVERABLE_COMPLETE`;
4. **есть ли у этой линии коммиты** — `git -C .claude/worktrees/<линия> log --oneline main..HEAD`,
   если воркдерево ещё существует; отметь отдельно, если дерева нет;
5. **дата файла** и **размер**.

Результат — одна таблица в `docs/handoff/INVISIBLE-DELIVERABLES-CENSUS-01/report.md`,
отсортированная так, чтобы наверху были случаи «воркер утверждает завершение, коммитов ноль» —
это работа, которую мы считали потерянной.

Внизу отчёта — три числа: сколько файлов всего, у скольких есть маркер завершения, у скольких
при этом ноль коммитов.

## Границы

- **Ничего не чинь и ничего не коммить сверх своего отчёта.** Никаких массовых `git add -f`:
  в репозитории работают другие линии, столкновение дороже задержки.
- Не правь `.gitignore`. Решение по нему принято и не пересматривается: список защищает улики
  линий друг от друга. Задача — увидеть, что потеряно, а не разрешить всё подряд.
- Не переподнимай никакие линии и не трогай `docs/leadv2/` (реестр, шина, замки, очередь
  слияний) — это общее состояние, его правка изнутри линии откатывает чужую работу.
- Файлы читай, не переписывай.

Пишешь ТОЛЬКО в `docs/handoff/INVISIBLE-DELIVERABLES-CENSUS-01/`.
Свой отчёт назови именно `report.md` — под этим именем `.gitignore` его пропустит; любое другое
имя исчезнет ровно так, как описано выше. После коммита проверь `git ls-files` глазами, а не
кодом возврата `git add`.

Не трогать: `main`, `.gitignore`, `tests/known-red-suites.txt`, `docs/leadv2/`.
