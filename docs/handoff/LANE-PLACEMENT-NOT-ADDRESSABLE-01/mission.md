# LANE-PLACEMENT-NOT-ADDRESSABLE-01 — dispatch must accept an explicit lane placement (--resume-lane / --worktree)

Repo: ~/Projects/leadv2 (canonical plugin). Three reproductions on 2026-08-03 of the same disease: a worker's PLACEMENT (which tree it edits) is not expressible by the dispatcher, so mission prose saying "work in worktree X" is ignored:
1. Cluster-M's M-8 fix round was dispatched into a NEW EMPTY worktree while the code it had to fix sat uncommitted in the ORIGINAL lane's tree (their session hand-copied 13 files as a workaround).
2. QUESTION-DELIVERY-OWNERSHIP-01's worker drifted out of its assigned worktree into the MAIN checkout because the mission header mentioned "Repo: ~/Projects/leadv2".
3. The morning codex lane wrote into nowhere for the same family of reasons (CODEX-LANE-IN-A-LEADV2-WORKTREE-WRITES-NOTHING-01).

MECHANISM (verified): leadv2-dispatch-code.sh keys the lane worktree on the task SIGNATURE — each new mission text hash gets a fresh `leadv2-lane-worktree.sh ensure`-created tree, exported as LEADV2_LANE_WORK_ROOT → WORK_ROOT (:267-269). There is no CLI arg to say "use THIS existing tree". A fix-round mission necessarily has different text → different sig8 → different, empty worktree.

REQUIREMENTS:
1. NEW FLAG `--resume-lane <task-sig8-or-founder-id>`: resolve the EXISTING lane worktree for that task (same resolution leadv2-lane-worktree.sh uses: .claude/worktrees/<sig8> under the target repo; accept founder_task_id too if the lane dir is named that way) and pin WORK_ROOT to it instead of ensure-creating a new one. Validation (hard-fail with a one-line reason, exit nonzero, NO ledger row, NO spawn): path exists; is a git worktree of THIS repo (git rev-parse --git-common-dir resolves into the target repo's .git); not currently claimed by a LIVE worker (reuse the same liveness probes the status-surface census uses — a live claim = refuse, this flag resumes finished/dead lanes, it does not hijack running ones).
2. NEW FLAG `--worktree <abs-path>`: same as --resume-lane but by explicit path, same validation. (Two spellings, one code path.)
3. The pinned placement must flow everywhere WORK_ROOT flows today: worker --cwd, review-gate diff_root, product-close LEADV2_LANE_WORK_ROOT, LANE_START_SHA derivation (start SHA = the pinned tree's HEAD, so the close-gate diff covers only the NEW round's changes — document this choice in a comment; if deriving from the pinned tree's HEAD would hide pre-existing uncommitted work from the diff, prefer merge-base semantics consistent with _pc_diff_base and say so in the report).
4. The new-worktree path (no flag) stays byte-identical in behavior. The flags compose with existing ones (--kind, --force etc.); --resume-lane + --worktree together = usage error.
5. WORKER PROMPT PIN: when a placement flag is used, prepend one line to the worker mission prompt: "WORKTREE PIN: all edits go in <path>; do NOT cd to the main checkout even if the mission text names it." (This addresses reproduction 2 — prose drift — at the prompt layer while the flag addresses the placement layer.)
6. NON-GOALS: no changes to leadv2-lane-worktree.sh ensure semantics, no ledger/terminal changes (LANDED-AT-SPAWN-01 just landed — do not touch its code), no product-close changes (a separate lane is mid-review on that file — leadv2-dispatch-product-close.sh is OFF-LIMITS this task), no fanout/supervisor changes.
7. TESTS: new suite with fixture repos (pattern: tests/test-landed-at-spawn.sh): (a) --resume-lane resolves an existing lane tree, worker cwd == that tree (stub launcher records it); (b) --worktree same by path; (c) validation refusals: nonexistent path, foreign-repo worktree, live-claimed lane (stub a live pid), both flags together; (d) no-flag dispatch unchanged (regression: fresh tree still created); (e) prompt pin line present in the worker prompt when flag used, absent otherwise. Register in run-core-offline.sh.
