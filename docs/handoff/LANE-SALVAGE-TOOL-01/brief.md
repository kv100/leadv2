# LANE-SALVAGE-TOOL-01 — 91 готовый коммит лежит в 39 ветках и не доезжает до main

## Замер (2026-09-04, ведущая)

Перепись всех каталогов линий (`docs/leadv2/LANE-CENSUS.md`):

| состояние | сколько |
|---|---|
| слито в main | 27 |
| **сделано, но НЕ влито — с настоящими коммитами** | **39 линий / 91 коммит** |
| сделано, но не влито — только отчёт | 29 |
| начато без результата | 16 |
| не начато | 23 |

Ещё 81 «коммит» оказались пустыми якорями линии — их из счёта исключили.

**Почему не доезжает.** Дельта каждой линии маленькая (1–20 файлов), но ветки отстали от main
на 8–1086 коммитов. `git merge` такой ветки откатывает main на сотни файлов — ровно то, что
описано в `LANE-MERGE-SILENTLY-REVERTS-MAIN-01`. Защита от этого влита ведущей вручную сегодня
(`be1f6ce2`, `leadv2-merge-safety-gate.sh`, сюита 10/10). Теперь нужен способ ПЕРЕНЕСТИ работу,
а не сливать ветку.

Ведущая проделала это руками на одной линии и получила ровно один конфликт — регистрационный
список в `tests/run-all.sh`, где обе стороны дописывали строки. Разрешается объединением. Это
не совпадение: `run-all.sh` схлопывался на слияниях четыре раза за сутки.

## Задача

Написать `plugins/leadv2/scripts/leadv2-lane-salvage.sh <lane-id>`, который на ОДНОЙ линии:

1. находит `merge-base main HEAD` её рабочего дерева и список коммитов, **исключая якорные**
   (`… anchor` в теме) и коммиты слияния;
2. создаёт ветку `salvage/<lane-id>` от **текущего** main;
3. переносит на неё рабочие коммиты;
4. **при конфликте не угадывает.** Единственное разрешаемое автоматически — список
   регистрации сюит в `tests/run-all.sh`, и только **объединением обеих сторон** (ни одна
   строка не теряется, закрывающая кавычка одна). Любой другой конфликт — остановка с
   отчётом, какие файлы и какие строки спорят;
5. прогоняет `tests/run-all.sh --scope changed` на результате;
6. пишет вердикт: `salvaged_green` / `salvaged_red` / `conflict` / `nothing_to_salvage`,
   с именем ветки и выводом сюит.

Скрипт **никогда не трогает main** — только создаёт ветку `salvage/*` и отчитывается. Слияние
делает ведущая.

Затем **прогнать его по всем 39 линиям** из `docs/leadv2/LANE-CENSUS.md` и положить сводную
таблицу вердиктов в `docs/handoff/LANE-SALVAGE-TOOL-01/report.md`.

## Приёмка

1. **Негативный контроль на каждое изменённое требование**, мутация ВНУТРИ тела функции,
   доказательство — пара `baseline_rc`/`mutated_rc` и красная строка, НЕ `diff_hash`.
   Обязательны три: (а) якорный коммит попал в перенос → красное; (б) объединение `run-all.sh`
   потеряло строку одной из сторон → красное; (в) скрипт коснулся main → красное.
2. **Десять прогонов подряд** сюиты, все коды возврата.
3. **Ни одной потерянной строки при объединении** — докажи сравнением: число
   зарегистрированных сюит после = число до слева + число справа минус общие.
4. Вердикт `salvaged_green` обязан означать «сюиты по изменённым файлам зелёные», а не
   «перенос прошёл». Перенос без прогона — это `salvaged_red` до доказательства.

## Границы

Правь `plugins/leadv2/scripts/leadv2-lane-salvage.sh` (новый), свою сюиту в
`plugins/leadv2/scripts/tests/`, свой каталог handoff, и ОДНУ строку регистрации в
`tests/run-all.sh` для своей сюиты.
Не трогать: `main` (ни коммитом, ни слиянием), `docs/leadv2/` кроме чтения переписи,
`tests/known-red-suites.txt`, ослабление ассертов, чужие рабочие деревья кроме чтения.
Отчёт — `report.md`.
