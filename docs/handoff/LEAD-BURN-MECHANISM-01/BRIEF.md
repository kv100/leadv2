**Fact 1 — cost per turn is FLAT.** Across the six heaviest opus sessions, cr/turn ranges
272,592 to 348,896 while session length ranges 1,168 to 3,101 turns. There is no upward trend
with length. Prompt caching is already absorbing the context re-send. **The bill is
`turns × ~300k`, so the only lever is the NUMBER of turns.** Any proposal whose mechanism is
"carry less context" must first falsify this; if cost/turn really is flat, trimming context
saves nothing and compaction saves nothing on turns already paid.

Arithmetic that follows: ~13 tool calls per founder message, each issued in its own turn, plus
roughly one self-inflicted notification for every 1.5 founder messages.

## The constraint that makes this hard

**Every one of these behaviours is already forbidden in writing, and the rules are ignored.**

- `.claude/CLAUDE.md`: *"Never explain what you just did between tool calls — silence protocol."*
  Measured violation: 11,356 turns, 45.8% of all turns, ~3.45B cr in one week.
- The harness prompt: *"Independent tool calls can run in parallel in one response."*
  Measured compliance: **zero**. Not "low" — 0 of 13,437.
- `~/.claude-work/CLAUDE.md` token discipline rule 1: *"Understand code through subagents."*
  Measured: 345 Agent calls against 10,188 Bash calls.
- The same file, rule 6: *"one watcher per journal, filter to the ONE line you act on."*
  Measured: 693 injected messages.

So **a proposal that adds a rule, a doctrine line, or a CLAUDE.md paragraph is rejected on
arrival.** That intervention has been tried on all four of these and has a measured success rate
of zero. What is wanted is a MECHANISM: something in `plugins/leadv2/hooks/` or
`plugins/leadv2/scripts/` that changes the outcome without the lead having to remember anything,
the way the bash-heredoc guard does — it refuses and names the alternative, and it works because
it does not depend on good intentions.

Consider, and do not treat this list as exhaustive or as endorsed:

- A PreToolUse hook that sees N consecutive single-call turns with no intervening user message
  and refuses the (N+1)th, printing the batched form.
- A gate on text-only assistant turns — harder, because the hook surface may not expose a turn
  with no tool call at all. **Check whether it does before proposing it**; if there is no hook
  event for a text-only turn, say so plainly, because that would mean the single largest line
  item (45.8%) is not reachable by any hook and the answer has to come from somewhere else.
- Moving the notification stream off the conversation: a digest the lead reads on demand instead
  of 693 individually-delivered messages.
- Raising the floor on delegation: making Bash-heavy investigation route to a subagent
  automatically rather than by the lead's judgment.

Each of your proposals must carry: the exact hook event or script it hangs on, whether that
surface actually exists today (verify, do not assume), the number of turns per week it would
have removed **from this measured data**, and the failure mode that makes it worse rather than
better. A mechanism that would have blocked legitimate work is not an improvement; say where
yours would misfire.

## What NOT to propose

- Anything that makes the lead ask the founder more questions. Turns are the cost.
- Switching the lead off Opus. That is the founder's own launch choice and is out of scope here;
  the same 0%-batching and 45.8%-narration shape would simply cost less per turn, which is
  treating the symptom. Note it as an option with its arithmetic if you like, but it is not
  the deliverable.
- Anything requiring the founder to change how he writes to the lead.
- A measurement plan instead of a proposal. The measurement is done; it is above.
