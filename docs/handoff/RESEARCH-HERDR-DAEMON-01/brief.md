| **Ownership** | `src/platform/mod.rs:104` `detach_server_daemon_command` (calls `libc::setsid()`); `src/server/autodetect.rs:187` `spawn_server_daemon` | The server is spawned as a **separate daemon process** that calls `setsid()` in `pre_exec`, moving itself into a new session — detached from the parent's process group/controlling terminal. | **Liveness** | `src/server/autodetect.rs:44` `is_server_listening_at` (real `connect()` to the socket, distinguishes `ConnectionRefused`/`NotFound` = stale from success = alive); `src/platform/linux.rs:439` `process_exists` (`kill(pid,0)`, returns true on `EPERM` too, false only on `ESRCH`) | Two-tier liveness: (1) socket-connect probe — a stale socket *file* existing is not treated as "alive," only a successful connect is; (2) PID probe explicitly treats `EPERM` (process exists, owned by someone else) as alive and only `ESRCH` (no such process) as dead — i.e. it separates "can't tell" from "confirmed dead." No heartbeat/timestamp liveness anywhere in the daemon. | We had (per your finding) 8 ways to lie about liveness, worst being "no record = dead." herdr's worst case (`ESRCH` unmapped) still fails toward "assume alive," never toward "assume dead." | **TAKE** | Directly answers your "state separate from dead" gap: replace any `[ -z "$pid_file" ] && echo dead` with `kill -0 "$pid" 2>&1` and branch on `ESRCH` vs everything else: absence-of-evidence is *never* proof of death. |
| **Checkpoint / crash safety** | `src/app/session.rs:13-33` `schedule_session_save`/`sync_session_save_schedule` (debounced 5s after any dirty flag); `src/persist/io.rs:44-58` `save_json_to_path` (write to `*.json.tmp`, then `fs::rename` — atomic); `src/persist/restore.rs:66` `restore` doc-comment: **"Each pane gets a fresh shell in its saved cwd."** | Checkpoint = layout/workspace/pane metadata (cwd, tab tree, active pane), written via debounced atomic tmp+rename every 5s of dirtiness — survives SIGKILL of the daemon because the write itself is atomic and independent of clean shutdown. Optional `session-history.json` also captures pane scrollback. **Crucially: it does NOT reattach to a still-running child process after a crash** — restore always launches a *new* shell in the saved directory. In-flight work in that shell (e.g. a running agent) is lost unless it's a recognized "agent session" resumable via `src/agent_resume.rs` (session-id based resume, not process reattachment). | Our "checkpoint" is inside the dying tree and isn't atomic-write; herdr's proves atomic tmp+rename is what survives SIGKILL, not SIGTERM handling. | **TAKE the atomic-write pattern only; do NOT assume process reattachment is possible** | This is the actual SIGKILL-safety mechanism (SIGTERM handlers prove nothing, per your framing) — `write tmp file; rename` is trivially portable to bash (`printf ... > f.tmp && mv f.tmp f`). But herdr's own design concedes it can't resurrect a killed subprocess either — it only resurrects *layout*, so our expectation should be "recover the queue/plan state," not "resume the exact interrupted computation." |
| **Restart** | `src/server/autodetect.rs:288` `auto_detect_launch` — checks `is_server_listening_at`, and only if false calls `spawn_server_daemon()` then `wait_for_server_socket` (15s timeout, 50ms poll, `src/server/autodetect.rs:19-22`) | **No supervisor, no systemd unit, no watchdog thread found anywhere in `src/`** (`grep -rn respawn/watchdog` hit only unrelated identifiers). Restart is entirely **lazy and client-triggered**: the next `herdr` invocation checks the socket, and if nothing answers, spawns a fresh daemon. Protection against double-spawn is implicit in the Unix-socket bind (second daemon's `bind()` fails if the path is already listened on), not an explicit lock. | We have no equivalent — nothing polls or relaunches; a dead line stays dead until a human notices. | **TAKE partially** | Confirms a cron/timer poller (`is_server_listening` equivalent: try to connect/kill-0, respawn if not) is *sufficient* — herdr ships no fancier mechanism than this. Don't over-build a systemd unit; a 1-minute cron doing the same connect-or-spawn check matches herdr's own bar.

## What to take first

Take **first**, in order: (1) the `write-tmp + rename` atomic-checkpoint pattern from
`persist/io.rs:44` — it's a 3-line bash fix and is the only thing that actually survives
SIGKILL, unlike our current in-tree writers; (2) the `kill -0` liveness check with `ESRCH`
vs-everything-else branching from `platform/linux.rs:439` — replaces every "absence = dead"
false-zero we measured tonight with "unknown defaults to alive." Both are directly
portable to bash today, no daemon required. The daemon/`setsid` ownership model
(`platform/mod.rs:104`) is the correct long-term shape — a detached process holding our
lines independent of the editor tree — but it's a bigger lift (needs a socket protocol,
not just a spawn call) and should follow once the two atomic fixes stop today's bleeding.
An external lazy-restart poller (cron, no systemd needed) closes the loop, matching
herdr's own "no watchdog, just retry-on-next-connect" bar.
