# REVIEW-GATE-SILENCE-READS-AS-PASS-01 — молчание гейта больше не читается как «прошло»

## Что было сломано

`leadv2-review-run.sh` пишет `review-gate.md` встроенно в каждой из двенадцати точек решения,
каждый раз `.tmp` + `mv -f`. Движок, умерший **между** этими точками — выход по `set -u` в
родительской области, сигнал от вотчера линии, ранний путь `wait` — не оставлял ни артефакта, ни
строки `review_gate`. Ниже по течению отсутствие гейта читается как «ничто не заблокировало»:
непроверенная линия выглядела проверенной. Это молчание **в разрешающую сторону**.

Измерено до правки (2026-09-06, на `main`):

```
$ git grep -nE 'gate_engine_aborted|_review_gate_terminal_fallback' main -- plugins/leadv2
(пусто)
$ git grep -nE "^\s*trap .*EXIT" main -- plugins/leadv2/scripts/leadv2-review-run.sh
(пусто)
```

Находка из триажа 49 веток: работа лежала на `worktree-7b9d819b` (REVIEW-ARM-FAILCLOSED-01,
08-25) и не приземлилась — 1 строка из 88 на main. При этом **FAILCLOSED-02 приземлился** и делает
другую половину (классификация rc выживших рук, `leadv2-review-run.sh:1123,1568,1593,1764` +
`test-review-arm-failclosed-nonzero.sh`). Тронут не был — случай (j) сюиты это стережёт.

## Что сделано — перенос L3, не слияние ветки

Ветка `7b9d819b` не сливалась и не удалялась: за месяц файл ушёл далеко (её версия конфликтует),
а из трёх слоёв исходной работы приземления требовал только L3.

`_review_gate_terminal_fallback` + `trap … EXIT` + три сигнальных trap-а, вставлены сразу после
определения `emit` (строка 134). Свойства, каждое проверено случаем в сюите:

- **только запасной писатель** — проверка отсутствия файла означает, что он не может затереть
  решение, которое движок уже записал;
- **не меняет код выхода** — статус снимается первым и переиспускается явно;
- **не срабатывает в подоболочках рук** — bash 3.2 сбрасывает пойманные trap-ы в `( )`, `$( )` и
  фоновых подоболочках. Проверено эмпирически на 3.2.57 (`GNU bash, version 3.2.57(1)-release`),
  а не принято на веру: если бы это было не так, каждая рука писала бы blocked-гейт поверх живого
  ревью;
- **сигнальные trap-ы обязательны** — один EXIT-trap никогда не срабатывает при неперехваченном
  сигнале, ядро убивает процесс мгновенно.

## Негативный контроль — пара, обе стороны, обе ПРОГНАНЫ

Идиома мутации сверена с целью до того, как я поверила хоть одному цвету:
`grep -cF -- '  if [[ ! -f "${HANDOFF}/review-gate.md" ]]; then'` → **1**. Обе мутации вставлены
**внутрь тела функции**, не на верхний уровень: вставка на верхнем уровне красит сюиту по другой
причине и читается как успех (на этом сгорел замер 2026-08-25). Прогонялось на копии дерева в
scratch, общее дерево не мутировалось.

| прогон | итог | что краснеет |
|---|---|---|
| честное дерево | **15/0** | — |
| A: «никогда не писать» (инверсия стража) | **7/8** | (a)(b)(c)(d)(e)(f)(f2)(g) |
| B: «писать всегда» (`if true; then`) | **13/2** | ровно (f)(f2), больше ничего |

Под A зелёными остаются четыре случая кода выхода (a2)(b2)(c2)(d2) плюс (h)(i)(j) — сюита
краснеет не «вся сразу». **B важнее A:** без него запасной писатель, затирающий настоящее решение
`status: pass`, прошёл бы насквозь, потому что все случаи смерти остались бы зелёными.

**Поправка к моему же заголовку.** Первый черновик объявлял, что (f) переживает мутацию A. Не
переживает: инвертированный страж пишет как раз тогда, когда гейт уже есть, и затирает его.
Заголовок исправлен по измерению, а не измерение подогнано под заголовок.

## Отбор в CI — доказан счётом `[SELECT]`, в обе стороны

Сюита самозарегистрирована заголовком `# run-all-triggers: leadv2-review-run.sh` (в этом репо
`EXTRA_SUITE_MAP` пуст, живой механизм — `scan_suite_triggers`, строки 145-214 `tests/run-all.sh`;
`--scope changed` смотрит `git diff --name-only HEAD`).

```
# движок изменён:
$ LEADV2_RUN_ALL_SELECT_ONLY=1 bash tests/run-all.sh --scope changed
[SELECT] всего: 77, среди них
[SELECT] .../tests/test-review-gate-terminal-fallback.sh
строк WARN / "not found": 0

# КОНТРОЛЬ — движок возвращён нетронутым:
[SELECT] всего: 7, вхождений моей сюиты: 0
```

Ноль WARN-строк существенен: единицу можно получить от `WARN: mapped suite not found on disk`, и
это был бы счёт имени, а не выбора.

## Чего это НЕ делает

Не чинит руку, которая умерла тихо и вернула пустой отчёт — это FAILCLOSED-02, и он уже на main.
Не превращает blocked-гейт в диагноз: `reason: gate_engine_aborted` говорит «движок оборвался», а
не почему. Причина остаётся в `rc:` и в журнале линии.
