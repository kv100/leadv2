## The criterion that distinguishes the two "no baseline" situations

The gate already reads the one witness that can answer "did this line create this
file?" — the diff itself (`diff_file`, the very subject of the check). During the
existing changed-path extraction the lib now also records every path whose **old
diff side is `/dev/null`** (git's new-file rendering, belt-and-braces with the
`new file mode` header line) into `new_paths`. Then, in
`_selfcheck_baseline_verdict`:

- baseline tree materialises, but the file has **no copy in it** → `FAIL_NEW_FILE`
  (was already `FAIL` before — same verdict, now named);
- baseline tree **cannot** materialise (`! _baseline_ok`) **and** the diff says the
  lane **created** the path → `FAIL_NEW_FILE` — this is the regression hole: such a
  file has no baseline copy *by construction*, so its red is attributable to
  exactly one party, the lane, and the fail-open has nothing to protect;
- baseline tree cannot materialise and the path **predates** the lane →
  `SKIP_UNRESOLVED` — genuine fail-open, H1 contract intact.

Both consumers of the verdict (the C3 suites path and the C4 falsification path)
render `FAIL_NEW_FILE` as a FAIL with a row naming the reason
(`FAIL (no_baseline:file_new_in_diff)` / `FAIL (test_failed:rc=N;file_new_in_diff)`);
the `failed_names` entry keeps the pre-existing shape
(`suites:test-<stem>` / `falsification:<rel>:test_failed`), so no downstream
consumer sees a new vocabulary.

**Why this criterion cannot be forged by the test's own content.** The diff file is
generated by the *caller*, never by the lane:
`leadv2-dispatch-product-close.sh:_pc_git_diff` (line ~2282) diffs the lane tree
against the base through a throwaway copy of the index with `git add -N` for
untracked paths. A file the lane created always renders with `--- /dev/null` on the
old side — the header shape is a property of git's rendering of (base, tree), and
the test file's bytes (what it prints, echoes or comments) have no channel into
that rendering. Live probe of the exact production idiom against a brand-new
untracked test file:

```
$ GIT_INDEX_FILE=$tmpidx git diff HEAD -- tests/ ':(exclude)docs/leadv2' ':(exclude)docs/handoff'
diff --git a/tests/test-forged.sh b/tests/test-forged.sh
new file mode 100644
index 0000000..fa1f4a2
--- /dev/null
+++ b/tests/test-forged.sh
@@ -0,0 +1,3 @@
+#!/usr/bin/env bash
+echo forged
```

`4a4ad8ad` is **not** reverted: its `SKIP_RED` arm (hereditarily red suite never
blamed on the lane) is untouched, and control 2 below proves it still behaves.
