## Почему раунд 2

Воркер раунда 1 умер внутри слияния `83c44855`, оставив шесть конфликтных файлов в общем
дереве. Лид отменила слияние (`git merge --abort`, конфликтов ноль, ветка цела — 12 файлов,
1971 вставка, проверено после отмены). Незакрытый мердж больше часа блокировал соседнюю
сессию: `git commit` в репо отказывал.

Отсюда главное правило раунда: **останавливаться между ветками, а не внутри одной.**
Коммит и строка отчёта — после КАЖДОЙ ветки, не копить до четвёртой.

## План

1. Перед каждым слиянием — `git checkout -- docs/LEAD_V2_STATE.md`. Он вечно грязный, и git
   отказывается сливать ещё ДО конфликтов; это отказ до конфликта, а выглядит как «ветка не
   сливается».
2. Петля `recover-merge.sh worktree-<имя>` разрешает контрольную плоскость в пользу main и
   откатывается, оставляя ровно конфликты кода.
3. Конфликты кода разрешать по смыслу, сохраняя ОБА намерения. Несовместимы — описать обе
   стороны в отчёте и оставить ветку неслитой. Молчаливый выбор стороны недопустим.
4. Перед коммитом каждого слияния — сверка файлов, которые могли трогать соседние сессии.
5. Коммит поимённо, строка в отчёт, следующая ветка.
