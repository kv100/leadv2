# W-LEAD-LAST-MILE-01 — финиш линии одной командой, чтобы лид решал, а не выполнял процедуру

Ряд `5c6d0ff8014e`. Приказ основателя 2026-09-10: взять в работу сейчас.

## Задача

Измерено 2026-09-10 на трёх линиях подряд: диспатчи ушли в **01:19, 02:09, 03:43** — три линии за
2ч24м, одновременно ни разу больше двух, при доктрине WIP=6 (`ONE-LEAD-SIX-LANES-01`). Армы ни при
чём: линии писали в ТРИ разных файла и могли стартовать одновременно. Серийность создавал лид —
каждый следующий диспатч ждал, пока предыдущая линия будет доведена **руками**:

1. прогнать её сюиту;
2. вставить мутацию ВНУТРЬ тела функции в НАСТОЯЩЕМ файле, прогнать, убедиться в красноте;
3. восстановить файл и доказать `git status --porcelain` = 0;
4. `git diff main $(git merge-tree --write-tree main <branch>)` — единственный прибор для вопроса
   «не откатит ли слияние main»;
5. `git merge --no-ff` с трейлерами `Landed-lane:` / `Landed-branch:`.

Это ~40 минут лида на линию, механических и повторяющихся. Решение лида — только одно: сливать или
нет. Остальное обязано быть командой.

## Правило — переиспользовать, а не писать третье

Два зрелых компонента уже есть, и их надо РАСШИРИТЬ:

- **`plugins/leadv2/scripts/leadv2-land.sh`** — «the single landing runner»: hygiene →
  merge-safety gate → ff main → push → land-ledger. Функции `land_hygiene_state`,
  `land_safety_gate`, `land_verify_landed`, `land_refuse_behind` уже на месте.
- **`plugins/leadv2/scripts/leadv2-mutation-control.sh`** (`WORKER-DOD-GATE-01`) — применяет
  мутацию и доказывает, что сюита краснеет; пишет артефакт, который принимает
  `lib/leadv2-dod-gate.sh`.

**Второй лендер и второй мутатор писать запрещено.** В отчёте назвать словами, что именно
расширено и в каком месте.

## Что сделать

### 1. Прибор merged-tree — его нет ни в одном из них
`grep -c "merge-tree"` по `leadv2-land.sh`, `leadv2-lane-outcome.sh`, `leadv2-branch-merged.sh`
даёт **0, 0, 0**. Значит вопрос «не откатит ли слияние main» сейчас не задаётся вообще.
Добавить проверку в `land_safety_gate`: слияние обязано ОТКАЗАТЬ, если merged-tree удаляет или
откатывает файлы main вне write set линии. Список файлов от кончика к кончику — не тот прибор и
доказательством не считается.

### 2. Мутация лида — на настоящем файле, а не на копии
`leadv2-mutation-control.sh` по своей же шапке мутирует **scratch-копию** линии. Это правильный
инструмент для ВОРКЕРА. Лиду нужен второй режим: та же мутация на НАСТОЯЩЕМ файле в чекауте линии,
с гарантированным восстановлением и доказательством `git status --porcelain` = 0 ПОСЛЕ. Мутация
своей копии доказательством для лида не считается — это причина, по которой лид сегодня делает это
руками.

Гарантия восстановления обязана держаться и при падении/прерывании (`trap`), а не только на
счастливом пути: незамеченная мутация, оставшаяся в файле, — это худший исход из возможных.

### 3. Одна команда финиша
Цепочка: прогон сюиты линии → мутация лида на настоящем файле → восстановление и проверка чистоты
→ merged-tree → merge с трейлерами. Любой красный шаг — **ненулевой код и отказ сливать**, с
строкой, называющей шаг. Имя команды назвать в отчёте.

### 4. Честный предел, записать до начала
Сейчас в корне `~/Projects/leadv2` **124** грязных записи (в основном untracked), и известный отказ
`pass_unlanded cause=root_dirty` срабатывает на них, хотя пересечения с файлами линии нет. Если
`land_hygiene_state` откажет по этой причине — это надо ПОКАЗАТЬ отдельной строкой, а не обойти
молча: отказ по грязи, не пересекающейся с write set линии, — сам по себе дефект, и его надо
назвать в отчёте (заводить отдельный ряд, а не чинить здесь).

## Приёмка — обязательный негативный контроль, проверяется лидом
1. Сюита: линия, чей merged-tree удаляет файл main вне её write set, получает ОТКАЗ с ненулевым
   кодом и строкой, называющей файл. Та же линия без удаления — проходит. Обе на ОДНОЙ фикстуре.
2. Сюита: мутация лида применяется к настоящему файлу, сюита краснеет, файл восстановлен,
   `git status --porcelain` = 0. И то же самое при прерывании посреди прогона (kill) —
   файл всё равно восстановлен.
3. Сюита: команда финиша отказывается сливать, когда мутация НЕ покраснела (то есть негативный
   контроль не доказан) — ненулевой код, строка называет шаг.
4. Негативный контроль: убрать проверку merged-tree ВНУТРИ тела `land_safety_gate` — сюита из п.1
   краснеет на названном тесте.
5. Зелёный и красный прогон целиком в отчёт, плюс артефакт в
   `docs/handoff/w-lead-last-mile/mutation-control/`. Лид прогонит мутацию независимо на настоящем
   файле.
