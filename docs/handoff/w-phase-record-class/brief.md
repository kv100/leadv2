# PHASE-RECORD-REJECTS-TWO-DOCUMENTED-TASK-CLASSES-01

## Что сломано, воспроизведено дважды 2026-09-10

`plugins/leadv2/scripts/leadv2-phase-record.sh:1112-1115`:

```bash
case "$cls" in
  Trivial|Light|Standard|Heavy) ;;
  *) _log_err "assert: invalid class '$cls'"; exit 4 ;;
esac
```

Классов, которые система выдаёт сама, шесть, а принимает эта проверка четыре. Не хватает
`Strategic` и `Bulk`.

**Это не теоретическая дыра — это тупик, который система устраивает себе сама.** Дважды подряд
диспатч ряда `4afa0ee2525a` умер так:

```
[leadv2-dispatch-code] phase_precondition_config_error task=7fbc5d3a
    detail=[leadv2-phase-record.sh] ERROR: assert: invalid class 'Strategic'
[leadv2-dispatch-code] active_lane_released task=7fbc5d3a id=4afa0ee2525a where=exit_trap
```

Второй раз — с явным `--task-class heavy` в командной строке. Флаг не помог, потому что класс
берётся не из него: `docs/handoff/4afa0ee2525a/brain.yaml:3` несёт `class: Strategic` при
`class_source: floor_held`. То есть **классификатор назначает `Strategic`, пол его удерживает, а
фазовый гейт того же плагина этот класс не принимает** — линия не может стартовать в принципе, и
обойти это флагом нельзя.

Словарь уже разъехался по трём файлам:
- `leadv2-cost-estimate.sh:134` — `CEILINGS = {"Light":0.50,"Standard":2.00,"Heavy":8.00,"Strategic":20.00}`;
- `leadv2-cost-estimate.sh:150,156` — `"Strategic"` отображается в `strategic` и в `heavy`;
- `leadv2-backlog-pump.sh:724` — `Standard|Heavy|Strategic) route="phases"`;
- `leadv2-dispatch-code.sh --help` — рекламирует `trivial|light|standard|heavy|strategic|bulk`.

Не знает про `Strategic` только `leadv2-phase-record.sh`.

## Подход — делать именно так

1. Добавить `Strategic` и `Bulk` в `case` на `:1113`. Проверить **вторую такую же проверку** на
   `:1341-1343` (`plan-for: invalid class`) — она обязана принимать тот же набор; если наборы
   разойдутся, дефект вернётся с другой стороны.
2. **Источник словаря сделать один.** Объявить допустимый набор один раз в этом файле (константа
   рядом с первой проверкой) и использовать его в обеих. Не заводить yaml, не тянуть зависимость —
   набор из шести слов, ему хватит константы; цель в том, чтобы третья проверка физически не могла
   появиться со своим списком.
3. Отказ на действительно неизвестном классе **сохранить** — тот же код возврата 4, то же
   сообщение. Мы чиним словарь, а не снимаем проверку.

**Чего НЕ делать:** не менять сам классификатор и не трогать `floor_held`; не менять `--help`; не
переименовывать классы; не трогать `leadv2-router.sh`, `leadv2-mission-lint.sh`,
`leadv2-claude-profile-select.sh`, хуки (по ним идут другие линии).

## Краевые случаи, решающие форму
- Регистр: система выдаёт `Strategic` с большой буквы, флаг командной строки — `strategic` с
  маленькой. Сказать в отчёте, какой регистр приходит в `phase-record` на самом деле, и принимать
  ровно его; молча приводить регистр — значит спрятать вторую половину дефекта.
- Пустой `--class` по-прежнему отказ, как сейчас.

## Приёмка
Поведение меняется — мутация обязательна, и парный положительный случай тоже:
- фикстура: `--class Strategic` → rc=0; `--class Bulk` → rc=0;
- парная фикстура: `--class Nonsense` → rc=4 и прежнее сообщение. Разница между случаями только в
  значении класса;
- обе проверки (`assert` и `plan-for`) принимают один и тот же набор — тест обязан звать обе.

Негативный контроль: убрать `Strategic` из общего набора **внутри тела функции** — краснеет
названный тест. Отчёт короткий: какой регистр приходит на самом деле, зелёный и красный прогон.
