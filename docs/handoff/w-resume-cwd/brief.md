# Команда возобновления уводит оператора не туда, и делает это молча

Ряд `0496501d1d82`. Это единственное, что держит старт волн.

## Дефект, найден живым прогоном, а не чтением

2026-09-10, боевой репо m3-market, настоящий транскрипт
`678952be-029b-486b-aa58-20f3b162000e.jsonl`. `leadv2-interactive-session-switch.sh --dry-run`
отработал целиком и выдал:

```
DRY-RUN resume: cd "-" && CLAUDE_CONFIG_DIR=".../.claude-work" claude --resume 678952be-...
```

`cd -` уводит в ПРЕДЫДУЩИЙ каталог, а не в репо сессии. Это не отсутствие ответа и не громкий
отказ — это исполняемая команда с тихо неверным ответом, в том самом артефакте, который оператор
копирует руками.

## Механизм назван точно, проверять нечего

`leadv2-interactive-session-switch.sh:116` берёт `cwd` из `tail -n 1` транскрипта. Последняя
строка завершённой сессии — запись `type=cost-state`, у которой `cwd` нет **структурно** (её
ключи: `hasUnknownModelCost`, `modelUsage`, `sessionId`, `startTime`, `totalAPIDuration`,
`totalCostUSD`, `totalDuration`). При этом верный `cwd` несут **14255 строк из 19904**, и он там
правильный: `/Users/kostiantyn.vlasenko/MythicalGames/m3-market`.

Значит промах не краевой, а **на каждом завершённом транскрипте**.

## Подход

1. Искать `cwd` по последней строке, **где он есть**, а не по последней строке вообще. Идти с
   конца — первая же запись с непустым строковым `cwd` побеждает; сессия не меняет каталог по
   ходу, но если бы меняла, последнее значение и есть верное.
2. Не нашли ни в одной строке — **громкий отказ** со своим словом причины, а не подстановка `-`.
   Тихая правдоподобная команда хуже отказа.
3. Ничего больше не трогать: ни детектор, ни `leadv2-account-switch.sh`, ни транспланацию, ни
   формат журнала, ни существующие фикстуры.

Транскрипт большой (19904 строки) — читать с конца, а не грузить целиком.

## Почему сюита этого не увидела

Она зелёная, 38/0, и у каждого из шести стражей своя фикстура — лид проверил парными негативами
(M1→case6, M2→case4, M3→case5, M4→case2, M5→case3, M6→case1, каждая мутация красит РОВНО свой
случай). Ни одна фикстура не сверяет `cwd` в команде возобновления с настоящим `cwd`
транскрипта. Дыра именно там.

## Приёмка

- **Фикстура, чья последняя строка — запись `type=cost-state` без `cwd`**, а верный `cwd` лежит
  выше: команда возобновления обязана нести настоящий каталог. Это ровно форма живого случая.
- **Фикстура, где `cwd` нет нигде**: громкий отказ со своим словом причины, никакой `-`.
- Мутация внутри тела на настоящем файле красит **ровно** новую фикстуру и не красит ни одну из
  шести существующих. Если роняет две — стражи не различены, работа не сделана.
- Прежние 38 остаются зелёными.
