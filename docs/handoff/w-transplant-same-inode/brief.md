# Транспланация никогда не может удаться: оба слота смотрят в одно дерево

Ряд `b7b09a41c2f7`. Последний шаг ряда `467462db0de5`, и он держит старт волн.

## Что дал полный живой прогон 2026-09-10T16:22Z

Не dry-run. Настоящий транскрипт m3-market
`678952be-029b-486b-aa58-20f3b162000e.jsonl`, развёрнутый путь плагина.

**Само переключение отработало и приёмку ряда выполнило:**

```
account-switch: OK switched from=personal to=work (score=46 binding=seven_day:46)
account-switch: observed_next_pick=work observed_score=46 -- the NEXT selection runs on the new account
account-switch: staying_children=2 pids=87767,88460 -- running sessions keep the old account until they exit
```

**А следующий шаг отказал:**

```
FAILED reason=transplant_target_exists -- ...678952be-....jsonl already exists;
never overwriting a session in the target slot
```

## Причина структурная, а не разовая — измерено

`~/.claude-work/projects` это **симлинк** на `~/.claude/projects` (создан 2026-09-08T20:00, тот
самый root-merge из `SD-SYNC-TRANSCRIPT-RESIDUE-AFTER-ROOT-MERGE-01`). Inode обоих путей
совпадает: **567096999**.

Значит цель транспланации **всегда** существует, потому что она и есть источник. Счастливый путь
скрипта на этой машине недостижим в принципе. Страж «не перезаписывать чужую сессию» сам по себе
верен — он защищает от неразрешимого.

## Подход

Когда источник и цель — **один inode**, транспланация выполнена по построению. Распознать это,
сказать об этом своим словом (не молча), и идти дальше к команде возобновления. Отказ остаётся
ровно для случая, когда в цели лежит **другой** файл.

Проверять именно совпадение inode (`stat`), а не равенство путей и не равенство содержимого:
пути разные, а содержимое сравнивать на 70 МБ незачем.

Побочно, и на это можно опереться: `claude --resume <uuid>` с
`CLAUDE_CONFIG_DIR=~/.claude-work` и так найдёт транскрипт — дерево общее.

## Чего НЕ делать

Не трогать симлинк `~/.claude-work/projects` — это состояние машины, не наше дело в этой линии.
Не ослаблять отказ для случая «в цели другой файл». Не трогать детектор,
`leadv2-account-switch.sh`, вывод `cwd` и восемь существующих фикстур.

## Приёмка

- фикстура «источник и цель — один inode» → `rc=0`, выдана команда возобновления, и в журнале
  своё слово про уже-выполненную транспланацию;
- фикстура «в цели лежит ДРУГОЙ файл» → прежний громкий отказ `transplant_target_exists`;
- мутация внутри тела на настоящем файле красит **ровно** свою фикстуру; восемь существующих
  остаются зелёными (сейчас сюита 48/0).
