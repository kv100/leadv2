1. `4811e46fdee0` — `:532-534` python `unregister`: переписывает файл без изменений,

2. `622a2688839a` — `:952-956` `leadv2_active_set_worktree`: no-op rc=0, когда целевой

3. `7780073d7881` — `:993-1009` + python `update_phase` `:547-573`: guard на отсутствующий

4. `80158b9df1d6` — `:1012-1021` + python `update_pulse` `:575-581`: то же самое, отметка

5. `d7a791c7ce36` — `:1106-1114` + python `set_worker_pid` `:743-772`: неизвестный `task_id`

6. `f9c01f58b283` — `:969-983` `leadv2_active_unregister`: rc=0 без разрегистрации, когда
   `active.yaml` отсутствует.

## Что сделать
Каждый из шести обязан **отказывать закрыто**. Для каждой точки явно выбрать и
обосновать в отчёте одно из двух:
- ненулевой rc, отличимый от других причин отказа (предпочтительно), **или**
- машиночитаемый сигнал «не найдено», на который вызывающий обязан ветвиться.
Затем пройти вызывающих (`grep -rn leadv2_active_ ~/Projects/leadv2`) и убедиться,
что новый ненулевой rc не проглатывается там через `|| true` или `$(...)` под `set -e`.
Отсутствие `active.yaml` — это отказ, а не «нечего делать».
