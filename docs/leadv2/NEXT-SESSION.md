## 4. Почему `main` не запушен, и что сделать после

Каждый push в `main` запускает воркфлоу. Первый и единственный прогон (`33694115147`) упал —
не из-за регрессии, а из-за macOS-формы `mktemp`. Пушить восемь слияний в красный CI значит
жечь минуты квоты на заведомо красных прогонах.

**Последовательность:**
1. Дождаться зелёной `CI-SUITES-ARE-MACOS-ONLY-01`, слить её.
2. `git -C ~/Projects/leadv2 push origin main` — один push на все слияния.
3. Дождаться зелёного прогона: `gh run list --workflow=test-suites.yml --limit 1`.
4. Только тогда включить обязательные проверки на `main` репозитория `kv100/leadv2`,
   контекст `run-all --scope changed`. Основатель дал явное разрешение 2026-09-02
   («в целом можешь через браузер сам, даю апрув»). Строка: `SD-CI-REQUIRE-STATUS-CHECKS-01`.
   Аккаунт: `gh auth switch --user kv100`, после — переключиться обратно.

## 8. Почему нужен был перезапуск сессии

`plugins/leadv2/hooks/hooks.json` изменил **состав** хуков (добавился форк-гард на SessionStart).
Тело хука перечитывается на каждом событии, а регистрация — только при старте сессии. Кэши
плагина (`~/.claude/plugins/cache/leadv2-local/leadv2/*/`) синхронизированы вручную в прошлой
сессии. С этого старта гард живой: он падает, если в любом репо появится настоящая копия
плагинного хука вместо симлинка.
